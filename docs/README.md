# Documentation

This directory contains all project documentation, organized by domain so that
business, technical, and operational knowledge can grow independently without
becoming disorganized.

## Structure

| Folder | Purpose |
|---|---|
| [01-business/](01-business/README.md) | Business requirements, context, and stakeholder needs |
| [02-architecture/](02-architecture/README.md) | System architecture, diagrams, and design documentation |
| [03-database/](03-database/README.md) | Data models, schemas, and database design |
| [04-api/](04-api/README.md) | API contracts, specifications, and integration documentation |
| [05-frontend/](05-frontend/README.md) | Frontend application design and conventions |
| [06-admin/](06-admin/README.md) | Admin/back-office application documentation |
| [07-security/](07-security/README.md) | Security policies, threat models, and compliance |
| [08-devops/](08-devops/README.md) | Infrastructure, deployment, and operations documentation |
| [09-development/](09-development/README.md) | Development workflow, standards, and contributor guidance |
| [adr/](adr/README.md) | Architecture Decision Records |
| [roadmap/](roadmap/README.md) | Project roadmap and milestone planning |

## Conventions

- Each folder contains its own `README.md` describing its purpose and scope.
- Documents use simple, consistent headers (`# Purpose`, `# Status`, `# Owner`, `# Last Updated`) until fully authored.
- Architecture decisions are recorded as individual files in [adr/](adr/README.md), not inline in other documents.
